# Real Kroger Benchmark Implementation Result

## Data source

- Provider: Kroger Public API
- Store: Kroger - Mt Zion (`locationId=02100946`)
- ZIP used for the location workflow: `61820`
- Snapshot retrieval: `2026-11-16T18:11:53.214509+00:00`
- Products: 722 total; 620 available in the frozen snapshot
- Failed product queries: 0

The snapshot is `benchmark/kroger_snapshots/02100946-20261116.json`.
Credentials are loaded from the ignored local `.env` and are not stored in the
snapshot, task files, results, or git history.

## Metadata retained

Each product can retain its real UPC, name, brand, Kroger category, price,
package size, sold-by mode, fulfillment flags, stock level, explicit
manufacturer declarations, allergen containment groups, ingredient statement,
nutrition per labeled serving, serving size, servings per package, and organic
claim.

- 521 products have a labeled protein value.
- 595 products have at least one allergen containment field.
- Organic status: 103 true, 594 false, 25 unknown.
- Explicit tag examples: 196 vegan, 173 gluten-free, 103 organic, 88
  dairy-free, and 79 nut-free. `nut_free` requires both explicit tree-nut-free
  and peanut-free declarations.

Missing fields remain unknown. The implementation does not infer allergies or
nutrition from product names and does not invent meal portions.

## Task set

`benchmark/scenarios_kroger.json` contains 20 fixed tasks:

- 5 explicit-list tasks
- 5 constrained tasks
- 5 goal/planning tasks
- 5 recovery tasks with deterministic stock-failure events
- Difficulty distribution: 4 easy, 8 medium, 8 hard
- Three instruction variants per task: high, medium, and low explicitness

All selectors use real UPCs from the snapshot. The task set is generated by
`scripts/build_kroger_scenarios.py`, making curation reproducible.

## Validation result

`tests/test_kroger_benchmark.py` checks provenance, roster shape, UPC validity,
metadata-backed dietary/protein constraints, the absence of invented portion
measures, recovery alternatives, and end-to-end feasibility through the public
shopping tools.

At implementation time, all 10 Kroger benchmark test methods passed. Every
reference cart for every task passed in all three instruction variants. This is
a feasibility/implementation result, not an LLM performance score: the oracle
replays hidden reference carts and must never be reported as an agent baseline.

## Experiment commands

Offline validation:

```bash
PYTHONPATH=src python3 -m unittest tests.test_kroger_benchmark -v
python3 scripts/run_benchmark.py --dataset kroger --agent oracle_validation --runs 1
```

LLM evaluation (uses the configured model API and may cost money):

```bash
.venv/bin/python scripts/run_llm_experiments.py --dataset kroger \
  --agents ours react direct_fc --runs 3 --workers 16
```

The experiment runner injects the selected catalog into each fresh environment
and writes catalog/scenario file paths plus SHA-256 hashes into `manifest.json`.
